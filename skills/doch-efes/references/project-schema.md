# סכימת `project.json`

קובץ הקלט היחיד שכל התוצרים ניזונים ממנו. דוגמה מלאה וממולאת:
`assets/project.example.json`.

## שני כללים שחייבים להכיר לפני מילוי

1. **כל שדה שמסתיים ב-`_pct` נמסר ביחידות אחוז.** `6` הוא 6%. `0.7` הוא 0.7%.
   `23` הוא 23%. אין ניחוש ואין זיהוי אוטומטי — גרסה מוקדמת של המנוע ניסתה
   לנחש אם הכותב התכוון ל-`6` או ל-`0.06`, והכלל "ערך מעל 1 הוא אחוזים" הפך
   שכ"ט של 1% לשכ"ט של 100% ועמלת אשראי של 0.75% לעמלה של 75%. סטיות של עשרות
   מיליוני ש"ח שנראות סבירות לגמרי בתא אקסל. כלל נוקשה עדיף על היוריסטיקה
   שנכשלת בשקט.
2. **סכומים ללא מע"מ; מחירי מכירה כוללי מע"מ.** זו המוסכמה הישראלית. שדה
   `revenue.prices_include_vat` שולט בכך; אם הוא `true` (ברירת המחדל) המנוע
   מחלק את מחירי המכירה ב-1+מע"מ ומודד את הרווח על ההכנסה נטו.

שדה שמושמט מקבל ברירת מחדל שמרנית, אבל **שדה שמושמט בלי שהמשתמש נשאל עליו
הוא ליקוי, לא ברירת מחדל.**

---

## `meta` — זיהוי

| שדה | תיאור |
|---|---|
| `project_name` | שם הפרויקט כפי שיופיע בכל התוצרים |
| `client` | מזמין הדוח |
| `location` | יישוב |
| `gush` / `helka` / `migrash` | זיהוי המקרקעין |
| `plan` | המצב התכנוני — מספר תב"ע ומועד אישור |
| `date` | תאריך עריכת הדוח |
| `mode` | `takan21` (פינוי-בינוי) או `short` (יזמי מקוצר) |
| `preparer` | עורך הדוח |

## `indexation` — הצמדה

| שדה | תיאור |
|---|---|
| `build_index_uplift_pct` | הצמדת עלויות הבנייה קדימה, מהמדד הידוע למועד הביצוע |
| `index_base` | נקודת המדד ותאריכה — למלא מ-`israeli-statistics` |
| `source` | אסמכתה |

## `land` — קרקע ורכישה

| שדה | תיאור |
|---|---|
| `purchase_price` | מחיר הרכישה או שווי הקרקע |
| `purchase_tax_rate` | שיעור מס רכישה. קרקע ונכס לא-מגורים: 6% (ראה `tax-rules.md` לגבי מנגנון ההשבה) |
| `legal_pct` / `legal_amount` | שכ"ט עו"ד — כאחוז ממחיר הקרקע או כסכום |
| `brokerage_pct` / `brokerage_amount` | דמי תיווך |
| `development_levies` | היטלי פיתוח בגין הקרקע |
| `other` | עלויות קרקע נוספות |

## `areas[]` — שטחים ועלות בנייה ישירה

מערך. כל איבר: `use` (סוג שימוש), `label` (תיאור לתצוגה), `sqm`,
`cost_per_sqm`, `source`. הפרד שטחים עיקריים משטחי שירות ומרתפים — עלות המ"ר
שונה מהותית ביניהם, וערבוב מעוות את עלות המ"ר המכור.

## `parking` — חניון

`spaces` (מספר מקומות), `cost_per_space`, `sqm_per_space` (ברירת מחדל 35;
התקנות נוקבות ב-25 כשטח תקני, והטווח הבנוי הריאלי 28–35 — ראה
`cost-benchmarks.md`), `source`.

## `direct_other[]` — עלויות ישירות נוספות

`label`, `amount`, `source`. למשל עבודות פיתוח ותשתית באתר.

## `indirect[]` — עלויות עקיפות

כל איבר מקבל **או** `amount` (סכום קבוע) **או** `pct` יחד עם `basis`:

| `basis` | האחוז מחושב מתוך |
|---|---|
| `direct` | סך עלויות הבנייה הישירות (ברירת מחדל) |
| `land` | סך עלות הקרקע |
| `revenue` | סך ההכנסות נטו ממע"מ |
| `revenue_gross` | סך ההכנסות ברוטו |
| `direct_and_land` | ישירות + קרקע |

בחירת הבסיס אינה טכנית — שיווק נמדד מההכנסות, תכנון נמדד מהבנייה. בסיס שגוי
מזיז את התוצאה בכמה נקודות אחוז.

## `tax` — מיסוי

| שדה | תיאור |
|---|---|
| `developer_type` | `company` או `individual` — קובע איזה שיעור מס יוחל |
| `corporate_tax_pct` | מס חברות |
| `individual_tax_pct` | שיעור שולי ליחיד כולל מס יסף |
| `vat_pct` | מע"מ |
| `betterment_levy` + `betterment_source` | היטל השבחה — אומדן מ-`property-planning-law-expert` |
| `rmi_permit_fee` + `rmi_source` | דמי היתר רמ"י |

יזם הבונה למכירה ממוסה כהכנסה פירותית (מלאי עסקי), לא במס שבח. פירוט
ב-`tax-rules.md`.

## `contingency_pct` / `contingency_base` — בצ"מ

הבסיס: `direct`, `direct_and_indirect` (ברירת מחדל), או `total`. הטווח המקובל
5%–10%; לחיזוק ותמ"א 38 גבוה יותר.

## `revenue` — הכנסות

`prices_include_vat` (בוליאני), ו-`items[]` שבו כל איבר:
`label`, `units`, `avg_sqm`, `price_per_sqm`, `source`. לחלופין `total_price`
במקום מכפלת יחידות×שטח×מחיר.

## `income_asset` — נכס מניב (אופציונלי)

`annual_noi`, `cap_rate` (באחוזים), `sqm`, `label`, `source`. שווי היציאה
מחושב כ-NOI חלקי שיעור ההיוון ומתווסף להכנסות כרכיב Exit. השאר `null` כשאין.

## `finance` — מימון

| שדה | תיאור |
|---|---|
| `equity` | הון עצמי. נספג ראשון בתזרים; רק מה שמעבר לו נושא ריבית |
| `credit_rate_pct` | ריבית שנתית. אם ריק — מחושב מ-`prime` + `spread` |
| `prime` / `spread` | חלופה לריבית ישירה |
| `fees_pct` | עמלות פתיחה וניהול, כאחוז ממסגרת האשראי |
| `warranty_pct` | ערבויות חוק מכר, כאחוז מההכנסות ברוטו |
| `loan_limit` | מסגרת אשראי. אם `null` — נגזרת משיא הניצול בתזרים |

## `schedule` — לוח זמנים

`start` (תאריך), `quarters` (מספר רבעונים), ושלוש עקומות פריסה שהמנוע מנרמל
בעצמו — הן משקלות יחסיות, לא אחוזים:

- `land_curve` — ברירת מחדל: הכול ברבעון הראשון.
- `cost_curve` — עקומת S טיפוסית, למשל `[0,1,2,3,4,5,5,5,4,3,2,1]`.
- `revenue_curve` — מכירות מואצות לקראת הסוף.

## `thresholds`

`min_profit_on_cost_pct` — סף הרווח היזמי. ברירת מחדל 15. **מדובר באחוז
מהעלויות, לא מההכנסות.**

## `sensitivity`

`price_steps`, `cost_steps` (אחוזי שינוי, למשל `[-10,-5,0,5,10]`),
`rate_steps_pp` (הפרשים בנקודות אחוז על הריבית).

## `benchmarks[]` — מנגנון סימון הסטייה

זה השדה שמפעיל את כלל ה-10%. כל איבר:

```json
{"label": "מחיר מכירה למ\"ר מגורים (₪)", "used": 25700, "reference": 24200,
 "source": "עסקאות השוואה, מאגר רשות המסים", "source_date": "23.08.2026"}
```

`label` חייב להיות **זהה** לתווית הפרמטר בגיליון ההנחות, אחרת ההערה לא תיצמד
לשורה הנכונה. סטייה מעל 10% מסומנת בצהוב בגיליון ההנחות, ברשימת הדגלים, בדוח
ובדשבורד — **בלי לשנות את הקלט**.

## `flags[]` — דגלים ידניים

דגלים שהמנוע לא יכול לגזור מהמספרים: תכנוניים, קנייניים, עתיקות, זיהום קרקע.
כל איבר: `level` (`red` / `amber`), `title`, `text`, `source`. הם מצטרפים
לדגלים שהמנוע גוזר לבד ואינם מחליפים אותם.

## `assumptions_notes[]` — הערות חופשיות

`label`, `value`, `source`. לתיעוד הנחות איכותניות שאין להן תא מספרי.
